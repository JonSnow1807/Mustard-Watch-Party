# Deploy

Production topology (~$7/mo total):

| Piece | Where | Tier | Why |
|---|---|---|---|
| Backend | Render Web Service | Starter (~$7/mo) | always-on WebSockets — the free tier spins down after idle and a ~50s cold start kills a live demo |
| Postgres | Neon | Free | doesn't expire (Render's free Postgres does); scale-to-zero cold-resume noted below |
| Redis | Render Key Value | Free (25MB, no persistence) | persistence is unnecessary **by design**: the store rehydrates from Postgres under a fresh `storeEpoch` ([SCALING.md §3](SCALING.md)) |
| Frontend | Vercel | Hobby (free) | static CRA build, SPA rewrites in `vercel.json` |

Prod runs **one instance of the same Redis code path** the 3-instance lab
proved (`REDIS_URL` set ⇒ Lua store + pub/sub adapter). Scale-out is a
dial, not a rewrite; multi-instance correctness is re-proven nightly in CI.

## One-time setup

1. **Neon**: create a project → copy the pooled `DATABASE_URL`
   (`...pooler...neon.tech/...?sslmode=require`).
2. **Render**: New → Blueprint → point at this repo (root `render.yaml` is
   picked up automatically: rootDir `video-sync-backend`, health check
   `/health`, migrations run in the start command). Then in the service's
   Environment tab set:
   - `DATABASE_URL` = the Neon URL
   - `REDIS_URL` = internal URL of a new Render Key Value instance
     (create it in the same region)
   - `FRONTEND_URL` = `https://<your-app>.vercel.app` (comma-separate to
     allowlist preview domains too)
   `JWT_SECRET` is generated by the blueprint.
3. **Vercel**: import the repo, root directory `video-sync-frontend`
   (`vercel.json` handles the rest). Set build-time env vars:
   - `REACT_APP_API_URL` = `https://<render-host>.onrender.com/api`
   - `REACT_APP_WS_URL` = `https://<render-host>.onrender.com`
   (Build-time: changing them requires a redeploy. socket.io-client
   upgrades https→wss itself.)
4. **UptimeRobot** (free): HTTP monitors on the Render `/health` URL and the
   Vercel URL; the `/health` payload distinguishes `ok` from `degraded`
   (Redis unreachable) — alert on non-200 or `"status":"degraded"`.

## Verify a deploy

- `curl https://<render-host>/health` → `{"status":"ok","redis":"ok"}`
- Two browsers on different networks: create a room, share the link, hold a
  synced session 10+ minutes; toggle one offline and watch it reconnect and
  converge (the HUD via `?debug=1` shows drift/θ live).

## Notes

- Neon scale-to-zero adds occasional first-query latency after idle; the
  health check keeps the pool warmer on Starter.
- Logs are JSON (nestjs-pino) — Render's log tail filters by level;
  `LOG_LEVEL=debug` for drift chatter.
- `/metrics` is Prometheus format; set `METRICS_TOKEN` in prod (the scrape
  then needs `Authorization: Bearer <token>`).
